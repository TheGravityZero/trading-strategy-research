# Mean Reversion: Z-score спреда с контролем режима

Реализация: `src/trading_strategy/strategies/mean_reversion.py`.
Запуск: `research/runners/run_mean_reversion.py`. Зависимости: основной пакет
и extra `research` (`statsmodels`). Используются только локальные ZIP-архивы Binance.

## Правила

- Список инструментов и train/test задаются до тестирования. Engle–Granger и
  OLS оцениваются только на train; используется существующий `select_pairs`.
  Поправка Holm применяется ко всем парам. Допускается только положительный beta.
- Спред: `Y - intercept - beta * X`. Коэффициенты фиксированы после train.
  Z-score на закрытии считается относительно **предыдущих** 120 свечей,
  стандартное отклонение — выборочное (`ddof=1`).
- При `2 <= Z < 3.5` открывается short Y / long X; при `-3.5 < Z <= -2` —
  long Y / short X. Исполнение на следующем open. При пересечении нуля — выход,
  даже если Z перескочил ноль. Усреднения и входа на свече выхода нет.
- Начальный gross notional равен капиталу отдельного счёта пары. Количества
  фиксируются до выхода, beta — отношение количеств, а не долларовых весов.
- Риск-фильтр: ADF фиксированного спреда за 240 свечей, лаг 1, без autolag,
  обновление каждые 24 свечи. Для входа требуется p < 0.05. Неудачная проверка
  закрывает текущую позицию на следующем open. Это эвристика контроля режима,
  не ML change-point detector и не гарантия стационарности; фильтр запаздывает.
- Защитные выходы: `|Z| >= 3.5`, убыток счёта относительно капитала перед входом
  от 5% по предыдущему close, либо 120 свечей удержания. После защитного выхода
  пауза 24 свечи. Стоп не гарантирует максимальный убыток 5% из-за гэпов.
- Комиссия 10 bps + проскальзывание 2 bps с фактического оборота каждой ноги
  при входе и выходе. Проскальзывание списывается как денежная издержка.
  Открытая позиция в конце данных ликвидируется по последнему close с издержками.

Все параметры в барах: на 4h окно 120 означает 20 суток, а окно 240 — 40 суток.
Расчёт ADF начинается с первого полного окна исходного ряда и обновляется по
фиксированной сетке. На исполнении используется результат предыдущего close.
Загрузчик проверяет полноту исходных минутных свечей до агрегации, не заполняет
пробелы ценами и отклоняет конфликтующие перекрывающиеся архивы.

## Воспроизведение

Из корня репозитория:

```bash
PYTHONPATH=src .venv/bin/python research/runners/run_mean_reversion.py \
  --symbols ADAUSDT AVAXUSDT BNBUSDT BTCUSDT DOGEUSDT ETHUSDT LINKUSDT LTCUSDT SOLUSDT XRPUSDT \
  --start 2025-07-01 --split 2026-01-01 --end 2026-07-01 --interval 4h \
  --output-dir research/reports/mean-reversion/all-crypto

PYTHONPATH=src .venv/bin/python -m unittest discover -s tests
```

Даты UTC, конец диапазона исключается. Все даты должны совпадать с границами
свечей. Параметры доступны через `--help`, например `--window`, `--entry`,
`--stop`, `--regime-window`, `--max-holding-bars`, `--stop-loss`, `--fee-bps`.

## Полученный результат

Train: 2025-07-01–2026-01-01; test: 2026-01-01–2026-07-01; таймфрейм 4h.
Проверены все 45 пар десяти локальных криптоактивов: **0 прошедших отбор,
0 сделок**. Порог не ослаблялся после просмотра результата. Это результат
фильтра отбора, а не измерение доходности активно торгующей стратегии.

- `all-crypto/selection.csv`: все 45 гипотез, beta, intercept, исходные и
  скорректированные p-values, решение об отборе.
- `all-crypto/metadata.json`: конфигурация, диапазон и статус `no_pairs_selected`.
- `latest/`: отдельно сохранён исходный запуск BTC/ETH/SOL (3 пары, также без отбора).

Если есть прошедшие отбор пары, launcher сохраняет для каждой `*_bars.csv`
с equity, drawdown, сигналами и издержками, и `*_trades.csv` с направлением,
временем входа/выхода, причиной выхода, длительностью и чистой доходностью.
Метрики относятся к независимым счетам пар, не к общему портфелю.

## Ограничения

Коинтеграция в прошлом не гарантирует возврата в будущем. Оценка предполагает
I(1) для исходных цен; отдельный тест порядка интегрированности не реализован.
Повторные ADF-проверки — защитный фильтр, не независимые статистические
доказательства. RSI, общий сектор или высокая корреляция сами по себе не
доказывают стационарность спреда; его среднее не обязано равняться нулю.

Funding, заём, ликвидность, маржинальные требования и ликвидация не моделируются;
при исчерпании капитала симуляция завершается ошибкой. Фильтр может пропустить
структурный сдвиг. Текущий набор доступных активов несёт survivorship bias.
Kalman и ML-детектор смены режима не включены в базовую реализацию. Для настройки
параметров нужен отдельный validation-период, без повторного использования test.
